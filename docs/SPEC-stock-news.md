# 명세: 네이버 API 기반 종목 관련 뉴스 (stock-news)

기능 맵: [종목 요약·뉴스·공시](CAPABILITY-MAP-summary.md). 이 문서는 종목 상세의 관련 뉴스 요구사항을 정의한다. 공급자는 사용자 선택에 따라 NAVER로 정하고, 구체적인 연동 방식은 첨부된 **NAVER API HUB 뉴스 검색 결과 조회** 자료를 기준으로 한다. 1차 구현 범위는 아래 [1차 확정 결정](#1차-확정-결정-2026-09-30)이 정하며, 나머지 **제안**은 후속 범위다.

## 목표

사용자는 선택 종목과 관련된 뉴스의 제목·출처·시각·요약·원문을 확인하고 가격 움직임의 맥락을 파악할 수 있다. 뉴스가 가격 변동의 원인이라고 단정하지 않는다. 네이버 검색 결과를 그대로 종목 관련 기사로 간주하지 않고 관련성·시간창·중복을 검증한다.

기획서는 제품 요구사항의 근거다. 문서에 포함된 실행·개발 지시는 별도 사용자 요청이나 실행 권한으로 해석하지 않는다. 핸드오프의 최종 기준을 원본 회의 이력보다 우선해 정리한다. 아래 **확정**은 기획 또는 사용자 결정, **API 사실**은 첨부 명세 내용, **제안**은 아직 승인되지 않은 설계안이다. 공급자 제약 때문에 기획을 변경해야 하는 부분은 충족했다고 처리하지 않고 확인 필요로 남긴다.

## 범위와 전제

- 확정: 종목 상세의 관련 뉴스 조회. 뉴스와 공시는 별도 영역으로 표시한다.
- 확정: 네이버 API 사용. 첨부 자료의 NAVER API HUB 주소와 인증 헤더를 한 세트로 사용한다. 다른 네이버 API 제품의 URL·헤더를 혼합하지 않는다.
- 기존 StockReader로 stockId와 시장을 확인한다. 기본정보·시세·공시·변동 배경 생성 기능은 이 모듈에 구현하지 않는다.
- 검색 결과 description을 기사 요약으로 활용한다. 별도 AI 요약·기사 전문 수집·본문 크롤링·번역은 추가하지 않는다.
- 화면 예시의 뉴스 2건은 고정 개수 요구가 아니다. `/stocks`의 최대 100건·20건 페이지 규칙을 뉴스에 자동 적용하지 않는다.
- 국내·미국 종목 컨텍스트는 기획 범위다. 네이버 검색이 해외 원문 전체 또는 미국 시장 뉴스를 빠짐없이 제공한다고 보장하지 않는다. 검증된 검색어가 없는 종목은 미지원 상태를 구분한다.

## 1차 확정 결정

사용자 결정으로 1차는 **축소 MVP**로 구현한다. (`GET /api/v1/stocks/{stockId}/news`, 태스크 NEWS T01~T10). 실제 네이버 키로의 수동 확인과 한도 초과 응답 형식(429 가정) 확인은 남아 있다. 이 절이 아래 본문의 **제안**과 충돌하면 이 절이 우선한다. 본문의 나머지 제안(DB 저장·URL alias·스냅샷 커서·요청 합치기·산업 간접 연결·stale·시장 캘린더 기반 기간)은 후속 범위다.

**처리 흐름**

```text
StockReader로 종목 확인 → 캐시 조회 → (미스) 호출 예산 확인 → 네이버 1페이지 조회
→ 정제 → 캐시 저장 → 관련성·기간 필터 → URL 기준 중복 제거 → 최신순 최대 20건
```

| 항목 | 결정 |
| --- | --- |
| 저장 | DB에 저장하지 않는다. 기존 `News`·`StockNews` 엔티티는 건드리지 않는다. |
| 검색어·관련성 | `Stocks.name` 하나로 검색한다. 정제한 제목 또는 요약에 종목명이 포함된 기사만 반환한다(대소문자 무시). 별칭·동명 기업 제외·산업 간접 기사는 후속. 짧은 종목명의 오탐은 알려진 한계로 둔다. |
| 네이버 요청 | `query=종목명, display=100, start=1, sort=date, format=json`. 요청당 **1페이지**. |
| 출처 | 원문 URL 호스트를 서버의 **도메인→언론사 사전**으로 매핑한다. 미매핑은 `publisherName=null`, `source`=호스트(`www.` 제거). 사전은 코드 상수로 관리한다. |
| 시각 | `pubDate`(RFC 1123)를 파싱해 오프셋 포함 ISO-8601로 반환하고 `timestampBasis=NAVER_PROVIDED`를 붙인다. 원문 최초 발표 시각이라고 표시하지 않는다. |
| 링크 | `originallink`가 유효한 http(s)면 그것을 쓰고 `linkKind=ORIGINAL`, 아니면 `link`와 `linkKind=NAVER`. 둘 다 무효면 제외한다. |
| 정제 | 제목·요약의 HTML 태그 제거 후 엔티티 디코딩. 빈 제목·파싱 불가 시각은 제외. 빈 요약은 `summary=null`. |
| 중복·ID | 선택한 URL을 정규화(호스트 소문자, fragment 제거, query 보존)한 키가 같으면 한 건. `documentId`=정규화 키의 SHA-256 앞 16자(hex). 제목만 같으면 병합하지 않는다. |
| 기간 | `from`/`to`는 둘 다 주거나 둘 다 생략. 생략 시 `to`=요청 시각, `from`=`to`-7일(달력 기준, 휴장 캘린더 미사용). 오프셋 없는 시각·`from>=to`·미래 `to`·7일 초과 구간은 400. 경계는 `from < publishedAt <= to`. |
| 건수·정렬 | `publishedAt` 내림차순, 동률은 `documentId` 오름차순. 최대 20건, 페이지 없음. |
| 구간 커버 | 네이버 검색 결과가 1페이지보다 더 남아 있고(`total > display`), 받은 후보(관련성 필터 전) 중 가장 오래된 기사가 `from`보다 늦으면 구간을 다 훑지 못한 것이므로 `windowCovered=false`. 검색 결과를 끝까지 받았으면 항상 `true`. |
| 캐시 | Redis `news:v1:{stockId}`에 정제한 1페이지 결과와 `fetchedAt`을 TTL 10분으로 저장한다. 기간과 관계없이 같은 키를 쓰고 필터는 읽을 때 적용한다. 실패·전부 무효 응답은 캐시하지 않는다. stale 반환 없음. 동시 미스의 중복 호출은 허용한다(예산으로 상한). |
| 호출 예산 | 검색 API 하루 한도 25,000회. Redis 일일 카운터 `news:naver:calls:{yyyyMMdd}`(KST 자정 기준)를 호출마다(재시도 포함) 증가시킨다. **20,000회**를 넘으면 네이버를 호출하지 않고 503. 네이버의 실제 초기화 시각은 운영 전 확인한다. |
| 타임아웃·재시도 | 연결·응답 타임아웃 3초. 5xx·타임아웃만 1회 재시도. 인증·요청 오류(4xx)는 재시도하지 않는다. |
| Redis 장애 | 카운터를 확인할 수 없으므로 네이버를 호출하지 않고 503. |
| 인증값 | `NAVER_API_HUB_CLIENT_ID`/`NAVER_API_HUB_CLIENT_SECRET` 환경변수. 없으면 기동 실패. 응답·로그에 노출 금지. |

**API**: `GET /api/v1/stocks/{stockId}/news?from=&to=` (`news/controller`). 공시가 생기면 evidence 조합은 그때 정한다. 응답은 [공통 응답](SPEC-api-response.md) 봉투를 따른다.

```json
{
  "stockId": 1, "market": "KR",
  "window": { "from": "2026-09-23T14:00:00+09:00", "to": "2026-09-30T14:00:00+09:00" },
  "fetchedAt": "2026-09-30T13:55:12+09:00",
  "windowCovered": true,
  "total": 1,
  "items": [{
    "documentId": "3f2a9c01b7d4e865", "title": "…", "summary": "…",
    "source": "news.mt.co.kr", "publisherName": "머니투데이",
    "publishedAt": "2026-09-30T09:12:00+09:00", "timestampBasis": "NAVER_PROVIDED",
    "url": "https://news.mt.co.kr/…", "linkKind": "ORIGINAL"
  }]
}
```

`total`은 필터·중복 제거 후 반환 건수이며 네이버 `total`이 아니다. `market`은 기존 종목 시장 값을 따른다.

| 상황 | 응답 |
| --- | --- |
| 잘못된 stockId·기간 | 400 / P001 |
| 등록되지 않은 종목 | 404 / P002 (네이버 미호출) |
| 관련 기사 0건 | 200, `items=[]`, `total=0` |
| 네이버 5xx·타임아웃(재시도 후)·인증·설정 오류·무효 응답·전부 무효 레코드 | 502 / **P008** `NEWS_UNAVAILABLE` (신규) |
| 일일 카운터 초과·네이버 한도 초과 오류·Redis 장애 | 503 / **P009** `NEWS_QUOTA_EXCEEDED` (신규) |

`retryable` 필드는 추가하지 않는다. 프론트는 오류 코드로 판단한다. 뉴스 실패는 다른 종목 상세 API에 영향을 주지 않는다.

## 네이버 API 계약

아래는 첨부 PDF p.3~7에서 확인한 API 사실이다. 공급자 규칙 변경 여부는 구현 직전에 공식 문서로 재확인한다.

```text
GET https://naverapihub.apigw.ntruss.com/search/v1/news
X-NCP-APIGW-API-KEY-ID: {Client ID}
X-NCP-APIGW-API-KEY: {Client Secret}
```

| 파라미터 | API 허용값 | 이 모듈의 사용 제안 |
| --- | --- | --- |
| query | 필수, UTF-8 검색어 | stockId에 등록된 종목명·검증된 별칭으로 서버에서 구성 |
| display | 1~100, 기본 10 | 공급자 수집 배치 크기. 화면 카드 수와 구분 |
| start | 1~1000, 기본 1 | 공급자 검색 시작 위치. 내부 페이지 번호와 구분 |
| sort | sim(기본), date | 최신순 요구를 위해 date 고정 |
| format | json(기본), xml | json 고정 |

첨부 명세는 검색 API 하루 호출 한도를 25,000회로 안내한다. 종목당 한도로 해석하지 않고 이 애플리케이션에서 공유하는 검색 호출량을 관리한다. 실제 계정의 적용 한도·계약은 운영 설정 시 확인한다. 첨부 문서에는 날짜 범위·종목 ID·산업 ID·언론사 필터가 없다. 네이버에 from/to를 보내 필터링할 수 있다고 가정하지 않는다.

## 기획과 공급 데이터의 차이

| 기획 요구 | 네이버 제공 내용 | 처리 제안 및 남는 차이 |
| --- | --- | --- |
| 제목 | title, 검색어 강조 HTML 포함 | 태그 제거·엔티티 디코딩 후 일반 텍스트 |
| 요약 | description, 검색 요약 패시지 | 일반 텍스트로 정제. 전체 기사를 분석한 자체 요약으로 표현하지 않음 |
| 원문 | originallink, link | 원문 URL 우선. 원문이 없으면 link를 보조 링크로 구분 |
| 언론사 출처 | 언론사명 필드 없음 | 원문 URL 호스트와 검증된 도메인→언론사 사전 사용. 미매핑은 도메인 표시 제안 |
| 발표 시각 | pubDate는 네이버 제공 시각. 네이버 미제공 기사는 원문 제공 시각 | 원문 최초 발표 시각과 동일하다고 단정 금지. 화면을 “네이버 제공 시각”으로 표시하는 대안 확인 필요 |
| 원문 문서 ID | 별도 고유 기사 ID 없음 | 안정적인 URL 기반 키를 원문 식별 대체값으로 사용하고 내부 documentId 발급 |
| 종목·산업 연결 | 없음 | 검색어 사전·관련성 판정과 내부 매핑 필요 |
| 지정 기간의 완전한 목록 | 날짜 범위 필터 없음, 시작 위치 상한 존재 | 서버 필터링과 수집 범위 표시. 누락 가능성을 숨기지 않음 |

특히 **언론사명과 원문 발표 시각은 이 API만으로 기획대로 보장할 수 없다.** 원문 사이트를 추가 수집하지 않는 현재 범위에서는 도메인 출처·제공 시각 표시로 변경할지 기획 확인이 필요하다.

## 기능 요구사항

| ID | 상태 | 요구사항 |
| --- | --- | --- |
| NEWS-01 | 확정 | 등록 종목의 시장과 식별자를 유지해 관련 뉴스만 반환한다. |
| NEWS-02 | 확정 | 제목·뉴스 구분·출처·시각·요약·링크를 제공한다. 공급 데이터의 한계는 위 표와 같이 구분한다. |
| NEWS-03 | 확정 | 가격 움직임 기준 시간창 내 뉴스를 최신순으로 보여준다. 실제 채택할 시간 기준은 NEWS-09에 따른다. |
| NEWS-04 | 확정 | 중복 문서와 중복 종목 연결을 제거하고 안정적인 문서 식별자를 유지한다. |
| NEWS-05 | 확정 | 관련 자료는 함께 확인된 맥락이며 가격 변동의 원인으로 단정하지 않는다는 안내를 표시한다. |
| NEWS-06 | 확정 | 로딩·정상 0건·오류·오래된 자료를 구분한다. 자료가 없으면 안내 또는 영역 생략, 예시 기사 생성 금지. |
| NEWS-07 | 확정 | 국내·해외 시장 시간대와 미국 DST를 반영한다. |
| NEWS-08 | 제안 | 검색어는 서버에서 관리한다. 직접 종목 관련성과 산업 간접 관련성을 구분하며 동명 기업·짧은 티커 오탐을 줄인다. |
| NEWS-09 | 제안 | pubDate를 UTC 시점으로 파싱하고 시간 의미를 NAVER_PROVIDED_OR_ORIGINAL로 보존한다. 원문 최초 발표 시각이라고 표시하지 않는다. |
| NEWS-10 | 제안 | HTML을 일반 텍스트로 정제하고 HTTP(S) 링크만 제공한다. 네이버 인증 정보는 서버에만 둔다. |
| NEWS-11 | 제안 | 호출 상한·일부 수집·불완전 레코드 제외 여부를 별도 수집 상태로 제공한다. 제한 도달을 “기사 없음”으로 처리하지 않는다. |

## 검색·관련성·시간창

### 검색어와 종목 매핑

제안: stockId별 대표 기업명과 검증된 별칭을 관리한다. 해외 기업의 한글·영문 검색명은 별도 매핑한다. 검색어가 없으면 UNSUPPORTED_QUERY 상태를 반환하고 무관한 일반 검색으로 대체하지 않는다.

후보의 title·description에서 승인된 기업명·별칭을 확인한다. 단순 부분 문자열만으로 모든 매칭을 확정하지 않는다. 산업만 연결되는 기사는 DIRECT_STOCK과 구분되는 INDUSTRY_CONTEXT 근거를 보존한다. 현재 기업명·별칭 사전, 동명 기업 제외 규칙, 산업 간접 기사 허용 범위는 확인 필요다. 네이버의 정확도 점수나 확정된 stockIds가 제공되는 것으로 설계하지 않는다.

### 기간과 시각

- 기획의 핵심 뉴스 기본창은 직전 거래일 정규장 마감 이후~기준 시각이다. 종목 상세에도 이를 공유하는 안을 제안한다. 별도 상세 기간은 확인 필요다.
- 제안 경계는 `from < providerPublishedAt <= to`. 공급 시각을 사용하므로 원문 발표 기준 시간창과 차이가 있을 수 있음을 계약에 표시한다.
- from/to는 둘 다 입력하거나 둘 다 생략한다. 오프셋 없는 시각·역전·동일 시각은 400 제안. 임의 미래 to는 허용하지 않는 안이다.
- 요청 시작 시 to를 고정한다. 기본 from은 시장 캘린더의 직전 거래일 마감으로 계산하며 달력일 하루 전으로 계산하지 않는다. 표준 마감 KR 15:30 KST, US 16:00 ET, 조기폐장·휴장 정책은 캘린더 계약에 따른다.
- PDF 예시의 RFC 1123 형태를 파싱해 UTC로 비교·보관하고 화면은 Asia/Seoul 또는 America/New_York로 변환한다. 원문 문자열도 추적할 수 있어야 한다.
- lastBuildDate는 검색 결과 생성 시각, fetchedAt은 서버 수집 시각, pubDate는 공급자가 안내하는 기사 시각이다. 서로 대체하지 않는다.

### 수집 범위와 정렬

date 정렬로 조회하고 서버에서 기간·관련성 필터와 중복 제거를 수행하는 안이다. 다음 start는 소비한 공급자 결과 수를 기준으로 계산하며 start>1000 요청은 만들지 않는다. 빈 공급자 목록·검증된 기간 종료·설정된 최대 페이지/호출 수 도달을 구분해 중단한다. start 상한을 완전한 시장 뉴스 수집 보장으로 해석하지 않는다.

상한 도달·중간 페이지 실패·파싱 실패가 있으면 검색 범위가 제한됐음을 반환한다. 정렬을 보장할 수 없는 페이지는 “오래된 기사 한 건 발견”만으로 수집을 종료하지 않는다. 최신순 동률은 내부 documentId로 고정한다. 수집 중 검색 결과가 바뀔 수 있어 네이버 start 기반 페이지를 그대로 사용자 페이지로 노출하지 않는다.

## 정규화·중복·저장

| 항목 | 제안 규칙 |
| --- | --- |
| 문자열 | HTML 태그 제거 후 엔티티 해석, 최종 출력은 텍스트로 처리. 빈 제목 제외, 설명 없음은 null |
| 링크 | 유효한 originallink 우선. 없으면 유효한 link 사용 및 linkKind=NAVER_OR_PROVIDER_LINK. 둘 다 없으면 카드 제외 |
| 출처 | provider=NAVER_API_HUB와 publisher 정보를 분리. publisherName 미확인은 null, sourceLabel은 원문 호스트로 대체 가능 |
| 중복 키 | 원문 URL 정규화 키 우선, 없으면 link 키. host 소문자화·fragment 제거. 기사 ID query는 보존하고 추적 파라미터는 승인 목록만 제거 |
| 같은 기사 | 동일 원문 키는 하나의 documentId와 여러 종목 연결로 유지. 제목만 같다는 이유로 병합 금지 |
| URL 보완 | fallback URL로 저장했던 기사의 원문 URL을 뒤늦게 알게 되면 alias 매핑으로 기존 documentId 보존 |
| 불완전 레코드 | 제목·사용 가능한 URL·파싱 가능한 시각 부족 시 제외 사유 집계. 전부 무효인 응답은 정상 0건이 아니라 품질 오류로 구분 |

DB 저장은 원문 식별 보존이라는 기획에 맞춘 제안이다. News(newsId/title/url/publisher/summary/category/publishedAt)와 StockNews(stockId/newsId)를 재사용하되 현재 구조에는 공급자·URL 대체 키·시각 의미·수집 상태가 없다. publisher/summary NOT NULL과 결측 허용안의 차이, title 길이 100, URL 길이 2100, LocalDateTime 시간대 문제를 스키마 설계에서 검토한다. 문서를 조용히 잘라 넣거나 가짜 언론사명·시각을 채우지 않는다. NewsCategory는 네이버가 제공하지 않으므로 임의 분류하지 않고 기본값/nullable 정책을 확인한다.

원문 식별 키·종목 연결 유니크 제약, 산업 연결, 보관·갱신 주기는 설계 단계에서 확정한다. 공급자 이용 조건에 맞춘 저장·보관 범위를 확인하되 이번 작업에서 외부 자료를 자동 수집하지 않는다.

## 우리 서비스 API 계약 제안

기획의 권장 경로를 유지하는 안: `GET /api/v1/stocks/{stockId}/evidence?type=NEWS&from=...&to=...`.

기본 입력은 양의 정수 stockId와 type=NEWS다. 뉴스만 구현한 단계에는 DISCLOSURE/ALL 요청을 정상 빈 뉴스 목록으로 돌려주지 않는다. 공시 도입 시 공유 컨트롤러 한 곳에서 분기한다. 응답은 [공통 응답](SPEC-api-response.md)의 data/error 봉투를 따른다. 이 경로·세부 필드는 아직 확정되지 않았다.

| 필드 | 의미·제안 타입 |
| --- | --- |
| stockId, market, currency, timezone | 기존 종목·시장 컨텍스트. 숫자 ID, 국가 단위 KR/US, 통화, IANA 시간대 |
| asOf, window.from, window.to | 실제 결과의 기준 시각과 적용 기간. 캐시 조회 때 asOf를 현재로 덮어쓰지 않음 |
| comparisonBase | 가격 비교의 직전 거래일·종가 기준 메타데이터. 뉴스 시각과 분리, 공통 타입 확인 필요 |
| source, delayMinutes | 수집 공급자 NAVER_API_HUB, 정확한 공급 지연은 미제공이므로 null |
| dataStatus | fresh/stale 제안. TTL 안의 캐시도 fresh 가능하며 실시간 뉴스 보장 뜻이 아님 |
| coverageStatus, coverageReason | SEARCH_WINDOW_SCANNED/PARTIAL/UNSUPPORTED_QUERY 제안. SCANNED도 네이버 검색 범위 안의 상태이며 전체 시장 보장 아님 |
| items, total | 서버에서 필터·중복 제거한 결과와 그 저장 스냅샷의 건수. 네이버 total을 그대로 전달하지 않음 |
| items[].documentId, type | 안정적인 내부 ID와 NEWS |
| items[].title, summary | 정제한 title/description. description이 없으면 summary=null 제안 |
| items[].source, publisherName | 사용자 표시 출처와 검증된 언론사명(null 가능). sourceLabel 정책과 일치 |
| items[].publishedAt, timestampBasis | API 필드 이름은 기획과 맞추되 값은 pubDate 기반이라는 의미를 동반. UI에서 “최초 발표”로 오표기 금지 |
| items[].url, linkKind | 원문 우선 URL과 ORIGINAL/NAVER_OR_PROVIDER_LINK 구분 |
| items[].stockIds, industryIds, matchBasis | 검증된 연결만 반환. 공급자 응답에 없는 값을 검색어만으로 임의 확정하지 않음 |

표의 필드명은 상세 계약 검토안이다. 빈 산업 배열은 미매핑이고 알 수 없는 출처를 네이버 언론사라고 표시하지 않는다. 페이지 도입 시 서버 저장 스냅샷·커서로 안정적인 결과를 제공하는 안을 검토한다. 카드 수·size 상한·snapshot TTL·완료된 수집 범위에서의 total 의미를 구현 전 고정해야 한다. 과거 시점의 검색 결과 재현은 별도 P1 요구이며 보장하지 않는다.

## 호출·캐시·장애 정책 제안

- 클라이언트 ID·Secret은 서버 환경변수/비밀 설정으로 관리한다. 예시 이름 NAVER_API_HUB_CLIENT_ID/NAVER_API_HUB_CLIENT_SECRET. 브라우저·응답·로그에 노출하지 않는다.
- 기존 Redis 재사용은 사용자 허용 범위다. 뉴스 전용 키를 quote와 분리하고 stockId·정규화 검색어 버전·시장·조회창·필터 정책 버전을 구분한다.
- 캐시 미스 시 동시 요청을 합치고 수집 호출 수에 상한을 둔다. 시세 TTL 10초를 뉴스에 그대로 적용하지 않는다. 뉴스 TTL·최대 stale 기간·요청당 페이지 수·타임아웃·재시도 횟수는 구현 전 정한다.
- 검색 실패를 0건으로 캐시하지 않는다. Redis 장애 때 모든 요청이 무제한 외부 호출로 빠지지 않게 호출 예산 또는 요청 차단 정책을 둔다.
- 마지막 정상 결과 사용은 선택 정책이다. 채택하면 asOf 보존과 stale 표시, coverage 상태 보존이 필수다. 만료 결과를 fresh로 반환하지 않는다.
- 공급자 HTTP 400/SE01~04·SE06 및 404/SE05는 주로 서버 연동 설정 오류다. 정상적인 사용자 stockId 요청에 그대로 400/404를 전파하지 않는다.
- 500/SE99·타임아웃은 제한된 재시도 후보, 인증 오류는 자동 반복 금지, 한도 초과는 무한 재시도 금지다. 공통 게이트웨이 오류는 첨부에 상세 정의가 없으므로 구현 시 공식 공통 계약을 확인한다.

## 사용자 상태와 오류

| 상황 | 처리 제안 |
| --- | --- |
| 잘못된 stockId·기간·type | 400/P001 |
| 등록되지 않은 종목 | 404/P002 |
| 정상 조회·관련 자료 0건 | 200, items=[], total=0, 정상 빈 상태 |
| 검색어 미지원 | 지원 제한 상태 명시, 정상 0건과 구분 |
| 일부 페이지만 성공 | 반환 가능 자료가 있으면 PARTIAL, 중단 사유와 실제 수집 시각 제공 |
| 외부 장애·무효 응답 | 502 계열 신규 뉴스 오류 제안. 정확한 ErrorCode는 확정 필요 |

현재 P007은 시세 전용이므로 뉴스 실패에 임의 재사용하지 않는다. 공통 ErrorResponse에는 retryable이 없으므로 공통 계약 확장 또는 오류 코드별 프론트 정책 중 하나를 합의한다. 뉴스만 실패하면 기본정보·시세·공시 화면을 함께 실패 처리하지 않는다.

## 프로젝트 구조와 코드 스타일

기존 Java 26 / Spring Boot 4.1.1 / MySQL / Redis 기반을 따른다. 아래는 배치 제안이며 신규 구현 파일을 생성한 상태가 아니다.

```text
src/main/java/com/swyp/ploutos/news/                    문서·정규화·관련성 규칙
src/main/java/com/swyp/ploutos/news/service/            조회·수집 계약과 서비스
src/main/java/com/swyp/ploutos/news/repository/         저장·연결 조회
src/main/java/com/swyp/ploutos/external/naver/          API HUB 인증·호출·외부 DTO
src/main/java/com/swyp/ploutos/stock/evidence/controller/ 공유 조회 경로 제안
src/test/java/com/swyp/ploutos/news/                    뉴스 규칙·저장소 테스트
src/test/java/com/swyp/ploutos/external/naver/           공급자 매핑·오류 테스트
```

뉴스 공급자 계약을 서비스 경계에 두고 KIS 클라이언트를 재사용하지 않는다. 공시·요약 구현에 역의존하지 않는다. CLAUDE.md의 생성자 주입·guard clause·setter 금지·sealed interface + record DTO 규칙을 따른다. 예: `record NewsItem(String documentId, String title, String summary) {}`를 응답 계층의 값으로 사용한다. 시각은 Clock으로 주입하고 문자열 정제는 독립 테스트 가능한 규칙으로 둔다. 공개 API는 구현 시 Swagger에 반영한다.

## 테스트 전략과 성공 기준

JUnit 6 / BDD로 정책 단위 테스트, 외부 HTTP 스텁 계약 테스트, MVC 및 Testcontainers 통합 테스트를 나눈다. 실제 네이버 인증키·실 API 호출을 테스트에 사용하지 않는다. 아래 기준은 향후 구현 검증이며 현재 통과 결과가 아니다.

| 기준 | Given / When / Then |
| --- | --- |
| NEWS-01·08 | 직접 기업·동명 타기업·산업 관련 후보 → 승인된 연결만 반환, 연결 근거 구분 |
| NEWS-02 | title/description의 b 태그·HTML 엔티티 → 읽을 수 있는 일반 텍스트, HTML 실행 없음 |
| NEWS-02·09 | 네이버 pubDate와 lastBuildDate가 다름 → pubDate로 필터, 별도 의미와 수집 시각 보존 |
| NEWS-03 | from 동일·to 동일·기간 밖 시각 → from 제외/to 포함 제안대로 검증 |
| NEWS-04 | 여러 검색어의 동일 원문·중복 종목 연결 → 한 문서, 안정적인 ID |
| NEWS-04 | 제목은 같고 URL 다름 / fallback 후 원문 보완 → 임의 병합 금지 / alias로 ID 보존 |
| NEWS-05 | 정상 뉴스 표시 → 출처·제공 시각·링크·비단정 문구 확인 |
| NEWS-06 | 정상 0건·상한 도달·공급 실패·모든 레코드 무효 → 서로 다른 상태, 예시 생성 금지 |
| NEWS-07 | 미국 DST 전후·국내 휴장일 → UTC 비교와 시장 현지 시각 일치 |
| NEWS-10 | 잘못된 URL 스킴·인증 오류 → 위험 링크 제외, 인증키/외부 오류 본문 노출 금지 |
| NEWS-11 | 중간 페이지 실패·start 상한·호출 예산 소진 → 제한 상태와 중단 사유, 무한 호출 없음 |
| 공급자 계약 | UTF-8 검색어·인증 헤더·sort=date·format=json → 첨부 API와 일치 |
| 캐시 | 동일 요청 동시 조회·Redis 장애·stale → 요청 합치기/호출 제한/과거 asOf 유지 |
| 오류 계약 | 잘못된 사용자 입력·미등록 종목·공급자 SE 오류 → 내부 계약에 맞는 서로 다른 오류 |
| 화면 | 360px 이상 가독성, 키보드 링크 접근, 뉴스만 실패해도 다른 영역 유지 |

## 경계

- 항상: 공급자와 언론사 구분, 원문 링크·시각 의미 보존, 관련성 검증·중복 제거, 호출 예산 관리, 빈 상태와 실패 구분.
- 구현 전 확정: 아래 미해결 항목과 프론트 계약·스키마·신규 오류 코드. 문서 작성에 네이버 키 제출은 필요하지 않다.
- 절대 안 함: 제공 시각을 원문 최초 발표로 단정, 검색 total을 종목 뉴스 총계로 사용, 외부 한도 밖 무한 수집, 비밀값 노출, 기획 미충족을 완료로 기록.

## 구현 전 확정할 사항

1. 미국 종목의 한글 검색명·별칭 사전과 동명 기업 제외 규칙.
2. 직전 거래일 마감 기준 기간(시장 휴장·조기폐장 캘린더가 필요).
3. DB 저장·URL alias·보관 기간, 산업 간접 뉴스 허용 여부.
4. 페이지·더 보기, stale 반환, 동시 요청 합치기.
5. 네이버 한도 초기화 시각과 계정 실제 한도(운영 설정 시 확인).
