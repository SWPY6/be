# 기능 맵: 산업 흐름·동향 (RQ-0201 ~ RQ-0205)

시장 요약 화면의 "오늘의 산업 흐름"과 그에 딸린 기능들을 구성하는 모듈과 빌드 순서다.
산업을 축으로 하는 이후 화면(산업별 동향, 오늘의 핵심 뉴스)도 같은 `industry` 모듈에 붙으므로 함께 기록한다.

종목 상세 화면의 기능 맵은 `CAPABILITY-MAP.md`에 따로 있다. 이 맵은 그 위에 얹힌다 —
`industry-flow`가 `stock-quote`의 `QuoteReader`를 쓴다.

## 모듈

| 모듈 id | 책임 | 의존 대상 | 명세 |
| --- | --- | --- | --- |
| `industry` | 산업 마스터 9종(`IndustryCode`, 한글 표시명), 산업별 종목 조회. HTTP API 없음 | — | `SPEC-industry.md` |
| `industry-flow` | 산업별 평균 등락률·순위·소속 종목 수. `GET /api/v1/industries/flows` | `industry`, `stock-quote` | **다음** — `SPEC-industry-flow.md` |
| `industry-trend` | 산업별 동향 화면: 산업 카드 + 소속 종목 목록, 상승·하락 필터 | `industry`, `industry-flow`, `stock-quote` | **추후** — 별도 명세 |
| `industry-news` | 오늘의 핵심 뉴스: 산업 단위 카드 + 관련 뉴스·공시 | `industry`, `industry-flow`, `news` | **추후** — 별도 명세 |
| `industry-pin` | 관심 산업 최대 3개 고정 | `industry`, 인증 | **추후** — 로그인 도입 후 |

빌드 순서: `industry` → `industry-flow` → (`industry-trend`, `industry-news`) → *로그인* → `industry-pin`

**지금 만드는 것은 `industry` 하나다.**

- `industry-flow`는 `stock-quote`를 기다린다. `SPEC-stock-quote.md`로 명세만 승인된 상태이고
  구현은 팀원이 진행 중이다(PR #22, #24 미머지).
- `industry-pin`은 **인증이 선행 조건**이고, 팀이 로그인을 마지막에 구현하기로 정했다.
  그래서 이 맵에서 가장 뒤다.

## 왜 이렇게 나누는가

- `industry`를 따로 두는 이유는 나머지 네 모듈이 **모두** 산업 마스터와 종목 매핑을 필요로 하기 때문이다.
  HTTP API가 없는 모듈이라는 선례는 `stock-daily-price`가 이미 만들어뒀다.
- 산업별 동향 화면도 `평균 등락률 N위`를 표시한다 → 같은 계산이므로 `industry-trend`가
  `industry-flow`를 재사용한다. 계산을 두 곳에 두면 두 화면의 순위가 어긋날 수 있다.
- 오늘의 핵심 뉴스도 `자동차 산업 +1.61% / 평균 등락률 1위`로 시작한다 → 같은 이유로 `industry-flow`에 의존한다.
- `industry-pin`은 시세와 무관하지만 **"이 요청이 누구인지"를 알아야** 저장할 수 있다.
  인증이 유일한 선행 조건이고 팀이 로그인을 마지막에 두기로 했으므로 함께 뒤로 간다.

## 프론트/백엔드 책임 경계

RQ-0201이 9개 산업을 **한 번에** 내려주므로 RQ-0202의 10초 자동 전환과 RQ-0203의 이전·다음
버튼은 재요청 없이 동작한다. `stock-chart`가 봉마다 OHLC를 다 주고 라인/캔들 전환을 프론트에
맡긴 것과 같은 패턴이다. 프론트는 폴링 주기(10초 권장)마다 9개를 새로 받아 갱신한다.

**RQ-0204 핀은 로그인 도입 후에 만든다.** 지금은 코드를 두지 않는다.

`userId`를 경로나 헤더로 받는 방식은 쓸 수 없다. 서버가 `permitAll`로 공개 배포된 상태라
누구나 남의 `userId`를 넣어 핀을 읽고 바꿀 수 있다(IDOR). 도메인·저장만 먼저 만들고 컨트롤러를
미루는 방안도 검토했지만, 로그인이 예정되어 있으므로 반쪽짜리 코드를 main에 넣지 않는다.

**로그인이 들어오면 정할 것:**

- **`Users`에 컬럼 3개가 아니라 별도 테이블 `user_pinned_industries`로 간다.** 컬럼 방식은
  "3개"라는 제약이 스키마에 굳고(5개로 늘리면 `ALTER TABLE` + 코드 전부), 같은 산업을 두 번
  고정하는 것을 앱이 컬럼 3개를 비교해 막아야 한다. 테이블이면 `UNIQUE(user_id, industry_id)`가
  DB 차원에서 막고, 빈 슬롯은 `NULL` 조합이 아니라 "행이 없음"으로 표현된다.
  `Users`는 계정 정보고 핀은 취향 데이터라는 점도 맞는다(CLAUDE.md "엔티티는 작게 유지").
- 최대 3개 제한은 DB 제약으로 표현할 수 없으므로 서비스에서 검증한다.
- 엔드포인트는 `GET`·`PUT /api/v1/users/me/pinned-industries`. `@AuthenticationPrincipal`로
  사용자를 얻는다. 경로에 `userId`를 두지 않는다.

## 공통 결정

| 항목 | 결정 |
| --- | --- |
| 등락률 기준 | **실시간 현재가.** `(현재가 − 직전 거래일 종가) ÷ 직전 거래일 종가 × 100`. `stock-quote`의 `Quote`가 계산한 값을 그대로 쓴다 — 국내·해외 기준을 통일하고 두 화면의 값이 어긋나지 않게 한다 |
| 평균 등락률 저장 | **저장하지 않는다.** 조회 시 계산한다. 현재가가 10초마다 바뀌므로 저장하면 즉시 낡는다. `stock-quote`의 "현재가를 DB에 저장하지 않는다"와 같은 이유다 |
| `Industries` 컬럼 추가 | **하지 않는다.** `Industries`는 9행 마스터(차원) 테이블이고 평균 등락률은 시점·시장마다 바뀌는 사실(fact)이다. 같은 산업이 국내와 미국에서 다른 값을 가지므로 컬럼 1개로 표현할 수 없다 |
| 순위 | **저장하지 않고 응답을 만들 때 정렬해 부여한다.** 순위는 나머지 8개와의 관계에서 나오는 파생값이라, 저장하면 한 산업만 갱신됐을 때 1위가 둘인 상태가 만들어진다. 9개 정렬은 비용이 없다 |
| 대상 종목 수 | **제한을 두지 않는다.** 산업에 매핑된 종목 전부를 평균에 반영한다 |
| 종목 수 임계값 | **대상 종목이 200개를 넘으면 구조를 재검토한다.** 한 요청이 N개 종목의 시세를 기다리는 구조는 N에 정비례해 느려진다(초당 20건 기준 270종목이면 13.5초). PR #24의 `QuoteRefresher`도 순차 호출이라 같은 한도를 공유한다 — 한 바퀴가 TTL(30초)보다 길어지면 갱신 전에 만료돼 캐시 미스가 상시화된다 |
| 시세 접근 | `stock-quote`가 노출하는 `QuoteReader`만 쓴다. Redis·KIS를 직접 만지지 않는다 |
| 활성 종목 부작용 | `QuoteRefresher`는 최근 `active-window-seconds`(60초) 안에 조회된 종목만 갱신한다. `industry-flow` 요청 한 번이 N개 종목을 활성화시켜 refresher 부하를 N배 올린다 — 위 임계값의 실질적 근거다 |
| 부분 실패 | 시세를 구하지 못한 종목은 평균에서 제외하고 나머지로 계산한다. 규칙은 `SPEC-industry-flow.md`에서 확정한다 |
| 소속 종목 수 | 평균에 실제로 반영된 종목 수를 표시한다(목업의 "소속 종목 4개 단순평균"과 같은 의미) |
| 시장 구분 | 쿼리 파라미터로 받는다. 국내·해외 **모두 같은 9개 산업**을 쓴다 |
| 산업 식별자 | 외부 API는 `IndustryCode`(`"AUTOMOBILE"`)로 식별한다. `industryId`는 내부 FK로만 쓰고 응답에 노출하지 않는다 — 환경마다 auto_increment 값이 달라질 수 있다 |
| 산업 표시명 | 한글명을 `IndustryCode` enum의 필드로 둔다. 지금은 주석뿐이라 API가 `"자동차"`를 내려줄 수 없고 가나다순 정렬도 불가능하다 |
| 표기 | 서버는 소수 둘째 자리로 반올림한 JSON number까지 책임진다. 부호·`%`·통화 기호 조립은 프론트다(`stock-quote`와 동일) |
| 시드 데이터 | `industries` 9행만 먼저 넣는다. `stock_industries` 매핑은 추후 |
| 스케줄러 | 두지 않는다. 현재가 갱신은 `stock-quote`의 `QuoteRefresher`가 이미 담당한다 |
| API 문서 | 명세의 "API 계약" 절을 프론트에 전달한다. 구현 후에는 Swagger(`/swagger-ui.html`)가 살아 있는 문서다 |

## 미해결 질문

- `stock_industries` 매핑 데이터를 언제·어떻게 채우는가. 매핑이 비면 `industry-flow`는 모든 산업의
  소속 종목 수가 0이 되어 평균을 계산할 수 없다. `industry-flow` 구현 전까지 확보해야 한다.
- 장 마감 후·주말에 `QuoteRefresher`가 계속 도는지(PR #24의 "남은 것"에 미정으로 적혀 있다).
  계속 돈다면 산업 흐름도 장외 시간에 같은 값을 반복 조회한다.
