# docs

기획서를 해석해 만든 **명세(spec)** 를 보관한다. `spec-driven-development` 스킬이 이 폴더에 명세를 쓴다.

## 파일 규약

| 파일 | 내용 |
|---|---|
| `SPEC-<모듈id>.md` | 모듈 하나의 명세. 목표, 명령어, 구조, 코드 스타일, 테스트 전략, 경계, 성공 기준 |
| `CAPABILITY-MAP.md` | 하나의 요구사항이 독립적으로 테스트 가능한 여러 기능에 걸칠 때만 만든다. 모듈 표와 빌드 순서 |

모듈 id는 케밥 케이스로 한 번 정하고 중간에 바꾸지 않는다. 명세, 계획, 태스크가 이 id로 서로를 가리킨다.

## 여기 없는 것

- **원본 기획서** — 보관하지 않는다. 채팅으로 전달받아 명세로 옮긴다.
- **구현 계획과 태스크 목록** — 진행 중인 작업 상태이므로 루트 `tasks/`에 둔다 (`tasks/plan.md`, `tasks/todo.md`).

## 명세는 살아 있는 문서다

결정이나 범위가 바뀌면 구현보다 명세를 먼저 고친다. 코드와 함께 커밋한다.
